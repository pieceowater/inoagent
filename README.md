# ai.inoagent

**Иноагент** — Claude Code в Telegram-группе с темами: сисадмин твоего сервера (root на нём) и
помощник для любых задач. Работает на подписке Claude (Pro или Max), живёт в Docker на том же
сервере, отвечает всем участникам одной группы и больше никому.

Установка руками или через свой Claude Code: [INSTALL-WITH-CLAUDE.md](INSTALL-WITH-CLAUDE.md).

Каждый ставит себе своего: сделай fork, запусти `make init` — и у тебя свой бот, свой сервер,
свои заметки. В репе нет ничего от конкретной установки: адрес сервера, группа и токены лежат
в gitignored-файлах, которые пишет установщик.

## Установка

Нужно:

- сервер на Ubuntu или Debian, вход по SSH-ключу, `sudo` без пароля (Docker поставится сам);
- на своём компе: `ansible`, `git`, `curl`, Node.js (для входа в Claude) и залогиненный
  [`gh`](https://cli.github.com) — им создаётся репа для заметок и добавляются deploy keys;
- подписка Claude Pro или Max и бот от [@BotFather](https://t.me/BotFather).

```bash
gh repo fork <эта репа> --clone && cd ai.inoagent
make init
```

`make init` спросит адрес сервера и токены, откроет браузер для входа в Claude, поставит всё
на сервер и попросит создать группу с темами и добавить туда бота админом. Как только в группе
появится сообщение, установщик сам впишет id группы и твой id и включит бота. Запускать
повторно безопасно.

Дальше: `make deploy` после правок в коде или настройках. Все настройки лежат в
`ansible/roles/inoagent/defaults/main.yml`, свои значения пиши в
`ansible/host_vars/<сервер>/vars.yml`.

## Что умеет

- **Сервер.** `host '<команда>'` выполняет команду прямо на хосте под root (`nsenter` в PID 1:
  контейнер privileged и делит с хостом пространство PID). Подтверждения по умолчанию выключены
  (`inoagent_approval_mode: "off"`). При `danger` или `all` опасные (или любые меняющие) действия
  ждут кнопку, нажать её может любой участник группы.
- **Темы.** Одна тема — один разговор со своей сессией Claude. Пока агент работает, в чате
  «печатает…».
- **Фото, файлы, голосовые.** Вложения скачиваются в `data/state/uploads` (хранятся неделю).
  Фото и PDF Claude смотрит сам, голосовые и кружки расшифровывает локальный Whisper
  (контейнер `whisper`, faster-whisper на CPU, наружу звук не уходит).
- **Файлы в ответ.** Презентации, документы, картинки агент кладёт в `$INOAGENT_OUTBOX` или
  отправляет через `send-file`. После ответа бот присылает их в тему и удаляет с сервера.
- **Кнопки.** `/menu` показывает постоянные кнопки рядом со скрепкой: лимиты, статус, стоп,
  новый разговор и быстрые команды. «Сделай быструю команду…» — и появится своя кнопка.
- **Лимиты.** `/limits` (крошечный запрос к haiku) показывает, сколько израсходовано из 5-часового и недельного окна
  подписки. Когда окно почти кончилось, бот предупреждает сам.
- **Память — Obsidian vault.** `data/workspace` (`Home.md`, `server/`, `incidents/`,
  `howto/`, `people/`). После каждого ответа бот пушит его в приватную репу `<твоя репа>.vault`.
  Склонируй её и открой в Obsidian. Свои правки можно пушить обратно.
- **Свой стиль.** `persona.md` в корне vault задаёт, как бот разговаривает (иначе действует
  нейтральный стиль из `internal/pkg/agent/svc/prompt/persona.md`). Подхватывается со
  следующего сообщения.
- **Меняет сам себя.** «Измени свой код, чтобы…» — агент правит свой клон репы (`/repo`),
  прогоняет `go vet` и `go test`, пушит в `main` и вызывает `self-deploy`. Хост пересобирает
  контейнер, итог приходит в ту же тему. Если сборка упала, работать продолжает старая версия.

## Как устроено

```
Telegram (long polling: белый IP не нужен)
   │
   ▼
inoagent (Go, контейнер) ── тема = сессия Claude (--resume) ── whisper (контейнер)
   │  claude -p --output-format stream-json
   ▼
Claude Code CLI ── PreToolUse-хук → inoagent-hook → unix-сокет → approval
   │  host '<команда>'
   ▼
nsenter в PID 1 хоста → root на сервере
```

Код устроен по образцу микросервисов lotof: `cmd/` (server, hook, healthcheck),
`internal/app.go`, `internal/core/*` (telegram, claude, asr, messenger, cfg), модули
`internal/pkg/{access,agent,approval}/{ctrl,svc,repo,ent}`. Правила агента лежат в
`internal/pkg/agent/svc/prompt/rules.md`: в них нет ничего про конкретный сервер, всё такое
агент узнаёт сам и записывает в vault.

## На сервере (`/opt/inoagent`)

| Путь | Что там |
|---|---|
| `data/claude` | конфиг и сессии Claude Code |
| `data/state` | `state.json` (тема → сессия, лимиты), `uploads/`, `outbox/` |
| `data/workspace` | vault агента |
| `data/whisper` | модели Whisper |
| `repo` | клон репы, из которого агент меняет и передеплоит себя |
| `secrets/ssh` | deploy keys для GitHub (код и vault) |

## Каждый день

```bash
make logs     # логи (без содержимого сообщений)
make status
make shell    # bash внутри контейнера
make test     # go test ./...
make deploy        # выкатить свои правки; перед этим git pull — агент тоже пушит в main
make quick-deploy  # только код бота, за минуту, без Ansible (.env и ключи не трогает)
```

Версия Claude Code закреплена в `Dockerfile` (`CLAUDE_CODE_VERSION`). Чтобы обновить: поменять
версию, сделать `make deploy` и проверить одно сообщение целиком.
